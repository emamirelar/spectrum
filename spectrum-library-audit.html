code A. TypeScript / Component API Inconsistencies

Prop signatures, type patterns, naming conventions, and watch decorators across all 42 components.

A1

Complex Prop Parsing Pattern — Incomplete Coverage High

The workspace rule mandates all complex props accept Type[] | string. Several components violate this:

  • spectrum-rail: moreContextActions: ContextMenuAction[] — missing | string
  • spectrum-dialog: buttons prop is object-only
  • spectrum-hero: slides is string-only (reversed problem)
  • spectrum-conversation-panel: messages, actions, sources all string-only
  • spectrum-theme: config is string-only
  • spectrum-image-gallery: Uses dual-prop anti-pattern (images + imagesJson)
  • spectrum-cookie-compliance: translation/config objects lack | string
  • spectrum-avatar: customStyle is object-only
A2

Union Type Ordering Inconsistency Low

spectrum-accordion and spectrum-menu put string first in their union types (string | Type[]), while every other component uses Type[] | string.

A3

Missing @Watch Declaration High

spectrum-data-table: defaultSort is parsed in parseInputs() but @Watch only covers data, config, columns. Changes to defaultSort alone won't trigger a re-parse.

A4

Duplicate @Watch Handlers High

spectrum-select has two separate @Watch('options') handlers: onOptionsChange() and handleOptionsChange(). These should be merged into one.

A5

Inconsistent size Scales Medium

Different components use different size vocabularies:

ComponentAccepted Size Values
spectrum-button'sm' | 'small' | 'base' | 'medium' | 'lg' | 'large' (6 values with aliases)
spectrum-chip'small' | 'medium' | 'large' | 'extra-small'
spectrum-text-input'small' | 'medium' | 'large'

Recommendation: Define a canonical SpectrumSize type and deprecate aliases.

A6

Inconsistent Prop Naming Medium

spectrum-conversation-panel uses conversationtitle (all lowercase) while every other component uses camelCase (dialogTitle, panelTitle, cardTitle, headerTitle).

bolt B. Event Naming and Payload Conflicts

Event name collisions, inconsistent payloads, and violations of the component events rule.

B1

Generic Event Name Collision High

spectrum-conversation-panel emits @Event({ eventName: 'action' }). The name action is too generic and risks collision when events bubble up the DOM.

B2

Shared Event Name, Different Components Medium

titleChanged is emitted by both spectrum-panel and spectrum-conversation-panel. Listeners cannot distinguish source without checking event.target.

B3

Same Event Name, Different Payload Shapes High

searchChange: On spectrum-rail it emits { action, value } (object). On spectrum-select it emits a bare string. Consumers expecting a consistent shape will break.

B4

Missing action Field in Event Payloads High

The events rule requires an action field. Violators:

  • spectrum-breadcrumb breadcrumbClick: emits { viewId, context, index }
  • spectrum-menu itemClick: emits { label, href? }
  • spectrum-text-input events: emit primitives/void
B5

Kebab-case Manual Event Dispatch Low

spectrum-context-menu dispatches a raw CustomEvent('menu-open') (kebab-case) alongside formal @Event declarations (actionClick, menuClose), bypassing Stencil's event system.

B6

debug State vs Prop High

spectrum-context-menu: debug is declared as @State() defaulting to true. Every other component declares it as @Prop() defaulting to false.

palette C. CSS / SCSS Duplication and Inconsistencies

Duplicated animations, missing shared partials, inconsistent breakpoints, and token usage across 43 SCSS files.

C1

Duplicated @keyframes Blocks High

The spinner animation (rotate 360deg) is copy-pasted across 9 files with varying names:

FileAnimation Name
spectrum-search-results.scssspin
spectrum-select.scssspin
spectrum-media-library.scssspin

spectrum-switch.scssswitch-spin

The ripple animation is also duplicated identically between spectrum-button.scss and spectrum-chip.scss.

C2

Duplicated .sr-only Utility High

Identical screen-reader-only CSS block copy-pasted in spectrum-switch.scss, spectrum-media-library.scss, and spectrum-application-layout.scss.

C3

No Shared SCSS Partials or Mixins Medium

The codebase has zero @mixin or @use statements. Every component is fully self-contained, leading to heavy duplication of:

  • Focus ring styles (different tokens per component)
  • Scrollbar styling (::-webkit-scrollbar)
  • Disabled state patterns (opacity: 0.5; pointer-events: none)
  • Transition declarations
  • prefers-reduced-motion and prefers-contrast: high media queries
C4

Inconsistent Breakpoints Medium

No single breakpoint scale exists. At least 8 different values are used:

BreakpointComponents Using It
480pxcookie-compliance, container, hero, search-results
600pxcontext-menu, image-gallery
640pxapp-layout, cluster
767pxchart, search-results, dashboard
768pxmenu, wizard, card, dialog, data-table
900pximage-gallery
1024pxdashboard, chart, cluster, app-layout, hero, menu
1100px / 1600pximage-gallery

The 767px vs 768px difference creates a 1px gap at the breakpoint boundary.

C5

Inconsistent Focus Ring Tokens Medium

Focus outlines reference different tokens across components:

  • var(--spectrum-sys-color-primary) — hero, search-results
  • var(--spectrum-color-primary, #1976d2) — dialog
  • var(--spectrum-color-primary) — cookie-compliance
  • Hardcoded #005fcc — application-layout
  • rgba(255, 255, 255, 0.5) — toast
C6

Orphan Design Token References Low

spectrum-image-gallery.scss references --spectrum-spacing-300, --spectrum-spacing-200, --spectrum-spacing-400 which do not exist in spectrum-variables.css. The component always falls back to hardcoded pixel values.

C7

BEM Naming Deviations Low

  • spectrum-image-gallery.scss uses .gallery, .gallery__grid, .modal-overlay instead of spectrum-image-gallery__*
  • spectrum-application-layout.scss uses .header-app-id, .content-navigation
  • spectrum-conversation-panel.scss uses .source-hover-overlay

menu_book D. Storybook Stories Issues

Duplicate titles, missing stories, phantom component references, and documentation gaps.

D1

Duplicate Story Titles — 8 Pairs High

Eight layout components have two story files with the same title, causing Storybook sidebar conflicts:

  • SpectrumGrid, SpectrumFlex, SpectrumStack, SpectrumCluster
  • SpectrumContainer, SpectrumAppLayout, SpectrumSidebar, SpectrumApplicationLayout

Each has one file under components/ and another under layouts/.

D2

Missing Stories Medium

  • spectrum-breadcrumb: No story file at all
  • dashboard-widget-host: No dedicated story (only visible inside dashboard stories)
D3

Overlapping MDX Documentation Low

spectrum-search-results has two use-case MDX files with nearly identical purpose: spectrum-search-results-use-cases.mdx and use-cases.mdx.

D4

Inconsistent Storybook Imports Low

Most stories import from @storybook/web-components-vite, but a few use the older @storybook/web-components: text-input, score-card, map, css-variables.

D5

Phantom Component References Medium

Storybook MDX docs reference spectrum-carousel and spectrum-megamenu which do not exist in the core package.

D6

Missing argTypes on Layout Stories Low

Layout stories under layouts/ mostly lack argTypes and Storybook controls, making them non-interactive.

inventory_2 E. Package and Export Issues

Type exports, version drift, dead code, and build configuration.

E1

Incomplete Type Exports from index.ts High

Only a subset of interfaces are re-exported. Many important types are not available from the barrel:

  • DialogButton, ContextMenuAction, CollapsibleListItem, BreadcrumbItem
  • FilterDefinition, AccordionSection, TableColumn, TableConfig, DefaultSort
  • CookieConsent, CookieTranslations, ImageConfig
  • Message, ContentCard, ExplorationItem, all dashboard types

Consumers must use deep imports or duplicate type definitions.

E3

TypeScript Version Mismatch Low

Root package.json: ^5.6.3 — Core package.json: ^5.7.3

E4

Dead Utility Code High

utils.ts exports a format() function that is only used in its own test file — never by any component.

E5

stencil.config.ts Minor Issue Low

F

Shadow DOM Inconsistency Low

No documented criteria for when shadow: true vs shadow: false is used. The split is roughly 50/50 across components. Additionally, spectrum-map is the only component that uses scoped: true.
