trending_up Why This Should Be Done

This migration delivers immediate, measurable improvements to the library's capabilities without breaking any existing projects.

design_services

Complete Design Token Coverage

Components currently rely on hardcoded fallback values because ~140 tokens are referenced but never defined. Defining them means a single change in spectrum-variables.css propagates everywhere — enabling global theming updates in seconds instead of component-by-component edits.

Developer Velocity
animation

Consistent Motion & Interaction

Today each component invents its own transition values. The M3 motion scale gives teams a shared vocabulary (short1-4, medium1-4, long1-4) so all animations feel coordinated and can be centrally tuned or disabled for prefers-reduced-motion.

UX Consistency
responsive_layout

Production-Ready Adaptive Layouts

New canonical layout shells (list-detail, supporting-pane, feed) give project teams pre-built responsive scaffolds that handle desktop→tablet→mobile transitions, eliminating 60-80% of custom layout work in new apps.

Time-to-Market
bug_report

Fix Silent Component Bugs

The chip selected state is visually broken (prop exists but does nothing), and the sidebar has an empty stylesheet. These fixes restore expected behavior that developers assume works but currently doesn't — reducing debugging time.

Quality & Trust
swap_horiz

Easier M3 Component Parity

With the full token system in place, future components (FAB, Navigation Drawer, Snackbar, etc.) can be built using the same variable references as Google's M3 spec, drastically reducing the design-to-code translation gap.

Future-Proofing
palette

Unlock UNOPS Color Palette

spectrum-colors.css defines 6 brand color scales and 8 gradients, but it's never imported into the build. Wiring it in gives every component access to the full organizational palette without any extra setup by consumers.

Brand Alignment
elevation

Predictable Depth & Elevation

A formal 6-level elevation scale replaces ad-hoc shadow values across components. Dialogs, menus, cards, and popovers share a clear visual hierarchy that's easy to reason about and customize per-project.

Visual Hierarchy
security

Zero Breaking Changes (by design)

The entire plan is additive. No existing token, prop, or default is removed. The single visual change (sidebar) is a documented bug fix — going from "renders nothing" to "renders the intended layout" — and is flagged as high-risk so teams can prepare.

palette Part 1: Full M3 Token System

Add ~140 new CSS custom properties to spectrum-variables.css. All are purely additive — no existing token is modified or removed.

1 Elevation Scale (6 tokens)

No Risk

Components like spectrum-menu, spectrum-dialog, and spectrum-card already reference --spectrum-sys-elevation-level-* with hardcoded fallbacks. Adding real definitions means fallbacks become redundant — visual output stays identical.

packages/core/src/styles/spectrum-variables.css
/* M3 Elevation Scale */ --spectrum-sys-elevation-level-0: none; --spectrum-sys-elevation-level-1: 0 1px 2px 0 rgba(0,0,0,0.3), 0 1px 3px 1px rgba(0,0,0,0.15); --spectrum-sys-elevation-level-2: 0 1px 2px 0 rgba(0,0,0,0.3), 0 2px 6px 2px rgba(0,0,0,0.15); --spectrum-sys-elevation-level-3: 0 4px 8px 3px rgba(0,0,0,0.15), 0 1px 3px 0 rgba(0,0,0,0.3); --spectrum-sys-elevation-level-4: 0 6px 10px 4px rgba(0,0,0,0.15), 0 2px 3px 0 rgba(0,0,0,0.3); --spectrum-sys-elevation-level-5: 0 8px 12px 6px rgba(0,0,0,0.15), 0 4px 4px 0 rgba(0,0,0,0.3);
verified Why safe: No existing :root or component defines these. Values match fallbacks already in use. spectrum-theme does not set these at runtime.

No Risk

/* M3 Shape Corner Scale */ --spectrum-sys-shape-corner-none: 0px; --spectrum-sys-shape-corner-extra-small: 4px; --spectrum-sys-shape-corner-small: 8px; --spectrum-sys-shape-corner-medium: 12px; --spectrum-sys-shape-corner-large: 16px; --spectrum-sys-shape-corner-large-increased: 20px; --spectrum-sys-shape-corner-extra-large: 28px; --spectrum-sys-shape-corner-extra-large-increased: 32px; --spectrum-sys-shape-corner-extra-extra-large: 48px; --spectrum-sys-shape-corner-full: 9999px;

No Risk

6 Spacing Scale Expansion (3 tokens)

Low Risk

Add finer spacing values below --spectrum-sys-spacing-small and one above --spectrum-sys-spacing-xx-large.

verified Mitigation applied: --spectrum-sys-spacing-2xs uses a fixed 4px value instead of a calc formula. --spectrum-sys-spacing-xs computes to 0.25rem which matches the fallback already used in 6 components (flex, stack, grid, chip, app-layout, data-table).

checklist Part 5: Library Audit Fixes

31 findings from the comprehensive library audit, organized by category with impact assessment for each fix. Same principles apply: add rather than modify or delete.

TS A. TypeScript / Component API

A1 Complex Prop Parsing — Incomplete Coverage

High
8 components violate the workspace rule requiring Type[] | string for complex props. Includes spectrum-rail, spectrum-dialog, spectrum-hero, spectrum-conversation-panel, spectrum-theme, spectrum-image-gallery, spectrum-cookie-compliance, spectrum-avatar.
bolt Impact: Enables pure HTML usage of components without JavaScript. Teams can paste component tags in CMS templates, server-rendered pages, or no-build setups. Removes the dual-prop anti-pattern (images + imagesJson) from image-gallery.

A2 Union Type Ordering Inconsistency

Low
spectrum-accordion and spectrum-menu use string | Type[] while every other component uses Type[] | string.
code Impact: Consistent developer experience. IDE autocompletion shows the primary type first across all components, reducing confusion when working with multiple components.

A3 Missing @Watch on defaultSort

High
spectrum-data-table: changing defaultSort at runtime has no effect because @Watch only covers data, config, columns.
bolt Impact: Dynamic sort control works as expected. Teams can programmatically change sort order without forcing a full component re-render. Fixes a silent bug in data-heavy applications.

A4 Duplicate @Watch('options') Handlers

High
spectrum-select has two separate handlers for the same prop: onOptionsChange() and handleOptionsChange(). Race condition potential.
bolt Impact: Eliminates potential race condition in select rendering. Options changes trigger one predictable code path. Reduces bundle size by removing dead code.

A5 Inconsistent size Scales

Medium
Button accepts 6 values ('sm' | 'small' | 'base' | 'medium' | 'lg' | 'large'), chip uses 4, text-input uses 3. No canonical SpectrumSize type.
code Impact: Teams stop guessing which size string works where. A shared SpectrumSize type provides IDE autocomplete consistency across all components. Existing aliases kept via union types (non-breaking).

A6 Prop Naming: conversationtitle

Medium
spectrum-conversation-panel uses all-lowercase conversationtitle while every other component uses camelCase (dialogTitle, panelTitle).
code Impact: Removes a naming inconsistency that forces developers to check docs. Add camelCase alias conversationTitle and deprecate the old name (non-breaking, both work).

EVT B. Event Naming and Payloads

B1 Generic Event Name Collision: 'action'

High
spectrum-conversation-panel emits a bare 'action' event. This name is too generic and collides when events bubble up the DOM.
bolt Impact: Fixes event listener conflicts in composite layouts. Parent components no longer accidentally catch unrelated 'action' events. Rename to 'conversationAction' with old name kept as deprecated alias.

B2 Shared Event Name: titleChanged

Medium
Both spectrum-panel and spectrum-conversation-panel emit titleChanged. Listeners cannot distinguish source without checking event.target.
code Impact: Unambiguous event handling. Prefix with component name (panelTitleChanged, conversationTitleChanged) so event delegation patterns work reliably.

B3 searchChange: Conflicting Payload Shapes

High
spectrum-rail emits { action, value } (object). spectrum-select emits a bare string. Same event name, incompatible types.
bolt Impact: Consistent event typing. Listeners can rely on a single interface. Fix by normalizing select's payload to { action: 'search', value: string } (additive wrapper, bare string still accessible via .detail.value).

B4 Missing action Field in Payloads

High
Rule requires action field. Violators: spectrum-breadcrumb (breadcrumbClick), spectrum-menu (itemClick), spectrum-text-input (primitives/void).
bolt Impact: Unified event handling patterns. Teams can build generic event processors that switch on e.detail.action across all Spectrum components. Reduces per-component event handling boilerplate.

B5 Kebab-case Manual CustomEvent

Low
spectrum-context-menu dispatches raw CustomEvent('menu-open') (kebab-case) alongside formal @Event declarations, bypassing Stencil's event system.
code Impact: All events go through Stencil's system consistently. Enables proper event documentation in generated docs and ensures composed: true propagation works across shadow DOM boundaries.

B6 debug as @State() defaulting true

High
spectrum-context-menu: debug is @State() defaulting to true. Every other component uses @Prop() defaulting to false.
bolt Impact: Removes unexpected console.log noise in production. The context menu currently logs debug info by default in every project using it. Fix: change to @Prop() debug = false.

CSS C. CSS / SCSS Architecture

C1 Duplicated @keyframes (9 spinners + ripple)

High
Identical spinner animation copy-pasted across 9 component SCSS files with varying names (spin, chart-spin, dashboard-spin, etc.). Ripple also duplicated between button and chip.
bolt Impact: Smaller bundle size (~2KB savings). Single animation definition means consistent spinner speed/easing everywhere. Future changes (e.g. branded loader) apply globally. Creates _animations.scss partial.

C2 Duplicated .sr-only Utility

High
Identical screen-reader-only CSS in spectrum-switch, spectrum-media-library, and spectrum-application-layout.
bolt Impact: Consistent accessibility support. A shared _utilities.scss partial ensures the sr-only pattern is always correct and up to date. New components get it for free.

C3 No Shared SCSS Partials or Mixins

Medium
Zero @mixin or @use statements. Heavy duplication of focus rings, scrollbar styling, disabled states, transitions, and media queries.
bolt Impact: Development speed and consistency. New components can @use shared partials instead of copying 20+ lines of boilerplate. Global fixes (e.g. focus ring update) propagate automatically.

C4 Inconsistent Breakpoints (8 different values)

Medium
No single breakpoint scale. Values range from 480px to 1600px with a problematic 767px vs 768px gap. Components respond at different viewport widths unpredictably.
bolt Impact: Predictable responsive behavior. Components within the same view breakpoint together instead of at random widths. Define canonical breakpoint tokens in spectrum-variables.css and migrate gradually (non-breaking: existing px values still work).

C5 Inconsistent Focus Ring Tokens

Medium
Focus outlines reference 5 different tokens/hardcoded values across components: --spectrum-sys-color-primary, --spectrum-color-primary, #005fcc, rgba(255,255,255,0.5).
