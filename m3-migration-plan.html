palette Part 1: Full M3 Token System

Add ~140 new CSS custom properties to spectrum-variables.css. All are purely additive — no existing token is modified or removed.

1 Elevation Scale (6 tokens)

No Risk

Components like spectrum-menu, spectrum-dialog, and spectrum-card already reference --spectrum-sys-elevation-level-* with hardcoded fallbacks. Adding real definitions means fallbacks become redundant — visual output stays identical.

packages/core/src/styles/spectrum-variables.css
/* M3 Elevation Scale */ --spectrum-sys-elevation-level-0: none; --spectrum-sys-elevation-level-1: 0 1px 2px 0 rgba(0,0,0,0.3), 0 1px 3px 1px rgba(0,0,0,0.15); --spectrum-sys-elevation-level-2: 0 1px 2px 0 rgba(0,0,0,0.3), 0 2px 6px 2px rgba(0,0,0,0.15); --spectrum-sys-elevation-level-3: 0 4px 8px 3px rgba(0,0,0,0.15), 0 1px 3px 0 rgba(0,0,0,0.3); --spectrum-sys-elevation-level-4: 0 6px 10px 4px rgba(0,0,0,0.15), 0 2px 3px 0 rgba(0,0,0,0.3); --spectrum-sys-elevation-level-5: 0 8px 12px 6px rgba(0,0,0,0.15), 0 4px 4px 0 rgba(0,0,0,0.3);
verified Why safe: No existing :root or component defines these. Values match fallbacks already in use. spectrum-theme does not set these at runtime.

6 Spacing Scale Expansion (3 tokens)

Low Risk

Add finer spacing values below --spectrum-sys-spacing-small and one above --spectrum-sys-spacing-xx-large.

--spectrum-sys-spacing-xs: calc(var(--spectrum-sys-spacing) / 4); /* 0.25rem at default */ --spectrum-sys-spacing-2xs: 4px; /* FIXED value, not derived */ --spectrum-sys-spacing-3xl: calc(var(--spectrum-sys-spacing) * 6); /* 6rem at default */
warning Edge case: spectrum-score-card.scss uses var(--spectrum-sys-spacing-2xs, 4px). If we derived from base (spacing/8 = 2px), gaps would shrink. Solution: Define as fixed 4px to match existing fallback exactly.
verified Mitigation applied: --spectrum-sys-spacing-2xs uses a fixed 4px value instead of a calc formula. --spectrum-sys-spacing-xs computes to 0.25rem which matches the fallback already used in 6 components (flex, stack, grid, chip, app-layout, data-table).

build Part 2: Component Variant Fixes

Targeted fixes for broken or missing variant behavior. Strategy: add new styles and props without modifying existing defaults.

10 spectrum-chip: Wire selected State

Low Risk

The selected prop exists but getChipClasses() never adds a CSS class for it. Chips with selected={true} look identical to unselected.

packages/core/src/components/spectrum-chip/spectrum-chip.tsx packages/core/src/components/spectrum-chip/spectrum-chip.scss
// TSX fix: add to getChipClasses() after disabled check if (this.selected) { classes.push('spectrum-chip--selected'); }
/* SCSS: new selected state (additive) */ .spectrum-chip--selected { background: var(--spectrum-sys-color-secondary-container, #d1e4ff); color: var(--spectrum-color-on-secondary-container, #001c3a); border-color: transparent; box-shadow: var(--spectrum-sys-elevation-level-1); }
verified Why safe: Component uses shadow: true — external CSS cannot target internal classes. Default selected={false} means no class is added unless explicitly opted in. No visual change for existing consumers.

11 spectrum-text-input: Filled / Outlined Variants

Medium Risk

M3 has two field styles. Spectrum currently ships one (outlined). Add variant prop with 'outlined' as default to preserve current look.

packages/core/src/components/spectrum-text-input/spectrum-text-input.tsx
// New prop (default preserves current appearance) @Prop() variant: 'outlined' | 'filled' = 'outlined';
/* SCSS strategy: existing rules stay as-is (= outlined default) */ /* Only .spectrum-text-input--filled adds NEW overrides */ .spectrum-text-input--filled .spectrum-text-input__wrapper { background: var(--spectrum-sys-color-surface-container-highest); border: none; border-bottom: 1px solid var(--input-border-color); border-radius: var(--spectrum-sys-shape-corner-extra-small) var(--spectrum-sys-shape-corner-extra-small) 0 0; }
warning Caution: This component uses shadow: false — external CSS CAN target internal classes. If consumers have selectors like .spectrum-text-input__wrapper { ... }, those still apply. The modifier class is new and won't conflict, but keep existing base selectors untouched.
verified Mitigation: Default variant='outlined' renders exactly the same DOM and class structure as today. The --filled modifier class is additive. Do NOT refactor existing wrapper rules into the --outlined block — leave them as the base.

grid_view Part 3: Canonical Layout Shells

New layout components inspired by M3 canonical patterns, plus fixing the broken spectrum-sidebar.

13 Fix spectrum-sidebar SCSS (Bug Fix)

High Risk

Current SCSS is literally :host { display: block; }. The component has full TSX logic (flex layout, widths, gaps, responsive, overlay, collapsed) but zero CSS implementation. Consumers today get vertically stacked <aside> + <main> (browser block flow).

/* TODAY (broken) */ :host { display: block; } /* AFTER FIX (implements documented behavior) */ :host { display: block; } .spectrum-sidebar { display: flex; min-height: 0; gap: var(--sidebar-gap, 1rem); } .spectrum-sidebar--right { flex-direction: row-reverse; } .spectrum-sidebar__sidebar { flex-shrink: 0; width: var(--sidebar-width, 280px); } .spectrum-sidebar__content { flex: 1; min-width: 0; } /* + collapsed, overlay, responsive breakpoint rules */
warning Breaking for existing consumers: Anyone using <spectrum-sidebar> today sees a vertical stack. After this fix, they'll see a proper sidebar layout. However: the component was never functional — its documented purpose is "sidebar + main content layout" which it never delivered. This is a bug fix, not a behavior change from its API contract.
verified Mitigation: Component uses shadow: true so external CSS isn't involved. Ship as part of a documented minor version bump. Consumers who relied on the broken vertical stacking (unlikely) can switch to <spectrum-stack> for that pattern.

Low Risk
