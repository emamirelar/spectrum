# Use Cases

## Overview

The `spectrum-chart` component is designed for diverse data visualization needs across analytics dashboards, reports, monitoring systems, and embedded visualizations.

## Primary Use Cases

### 1. Analytics Dashboards

**Scenario**: Executive dashboard showing key business metrics

**Implementation**:
```html
<!-- Revenue Trend -->
<spectrum-chart
  type="line"
  config='{"title":"Revenue Trend","valueFormat":"currency","showLegend":true}'
  data='{"labels":["Q1","Q2","Q3","Q4"],"datasets":[{"label":"Revenue","data":[500000,550000,600000,650000]}]}'
  height="400px"
></spectrum-chart>

<!-- Market Share -->
<spectrum-chart
  type="pie"
  config='{"title":"Market Share","showLegend":true,"legendPosition":"right"}'
  data='{"labels":["Us","Competitor A","Competitor B","Others"],"datasets":[{"label":"Share","data":[35,25,20,20]}]}'
  height="400px"
></spectrum-chart>
```

**Benefits**:
- Multiple chart types for different data types
- Responsive layouts adapt to screen size
- Professional appearance with Spectrum design
- Fast rendering for real-time updates

## Dashboard Integration Use Cases

### 9. Multi-Widget Dashboard

**Scenario**: Comprehensive analytics dashboard with multiple charts

**Implementation**:
```json
{
  "id": "analytics-dashboard",
  "layout": {
    "template": [
      "kpi1 kpi2 kpi3 kpi4",
      "revenue revenue market market",
      "category category performance performance"
    ],
    "gap": "24px",
    "columns": "1fr 1fr 1fr 1fr"
  },
  "widgets": {
    "revenue": {
      "component": "line-chart",
      "dataSourceId": "sales-data",
      "uiConfig": {
        "type": "line",
        "title": "Revenue Trend",
        "valueFormat": "currency"
      }
    },
    "market": {
      "component": "pie-chart",
      "dataSourceId": "market-data",
      "uiConfig": {
        "type": "pie",
        "title": "Market Share"
      }
    }
  }
}
```

**Benefits**:
- Single configuration for entire dashboard
- Shared data sources (no duplicate API calls)
- Centralized filter management
- Consistent styling

### 10. Filtered Dashboard with Dynamic Data

**Scenario**: Dashboard with region/date filters affecting multiple charts

**Implementation**:
```json
{
  "dataSources": {
    "sales-data": {
      "id": "sales-data",
      "endpoint": "/api/sales",
      "supportsServerFiltering": true,
      "filterParamMap": {
        "region": "region",
        "dateRange": "date_range"
      }
    }
  },
  "widgets": {
    "chart1": {
      "component": "line-chart",
      "dataSourceId": "sales-data",
      "filtering": {
        "subscribe": ["region", "dateRange"],
        "mode": "server"
      },
      "uiConfig": {
        "type": "line",
        "title": "Regional Sales"
      }
    }
  }
}
```

**Benefits**:
- Automatic filter propagation
- Server-side filtering (efficient)
- Smart caching by filter state
- Widget independence

## Best Practices by Use Case

### When to Use Each Chart Type

| Use Case | Recommended Chart | Why |
|----------|-------------------|-----|
| Trends over time | Line | Shows progression clearly |
| Category comparison | Bar | Easy to compare values |
| Part-to-whole | Pie/Doughnut | Shows proportions |
| Multi-dimensional data | Radar | Compares multiple variables |
| Correlation | Scatter | Shows relationship between variables |
| Distribution | Polar Area | Circular category visualization |
| Stacked categories | Stacked Bar | Shows totals + composition |

### Performance Considerations

- **Small datasets** (< 100 points): Any chart type
- **Medium datasets** (100-1000 points): Line, Bar, Scatter
- **Large datasets** (> 1000 points): Aggregated Line, consider data sampling
- **Real-time updates**: Disable animations, use efficient data updates

### Accessibility Considerations

- Always provide meaningful titles
- Use legends for multi-dataset charts
- Ensure sufficient color contrast
- Provide text alternatives for critical data
- Support keyboard navigation

---

## Anti-Patterns (What to Avoid)

❌ **Too many datasets on one chart** - Keep it simple (max 3-5 datasets)
❌ **3D charts** - Not supported, and harder to read accurately
❌ **Pie charts with too many slices** - Use bar chart instead (max 7 slices)
❌ **Dual Y-axes** - Can be misleading, use separate charts
❌ **Overly complex charts** - Break into multiple simpler visualizations
