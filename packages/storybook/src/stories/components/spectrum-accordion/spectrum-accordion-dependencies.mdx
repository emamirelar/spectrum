# 🔗 Spectrum Accordion Dependencies

This document shows the dependency relationships for the spectrum-accordion component and how it integrates with other components in the Spectrum system.

---

## 📋 Component Usage Overview

**spectrum-accordion** is a Level 2 composed component that depends on spectrum-chip internally and provides collapsible content functionality. It serves as a foundational content organization element used by 1 other component and offers two distinct variants for different use cases.

### Dependencies
- **spectrum-chip** (used internally by chip variant for trigger button)

### Components Using spectrum-accordion

- **spectrum-conversation-panel** (expandable content sections in chat interfaces)

## 🏗️ Architecture Integration

### Chip Integration Pattern
The accordion component uses spectrum-chip internally for the chip variant trigger button:

```typescript
// Internal chip usage in chip variant
render() {
  if (this.variant === 'chip') {
    return (
      <div class="spectrum-accordion spectrum-accordion--chip">
        <spectrum-chip
          variant={this.chipVariant}
          label={this.label}
          leadingIcon={this.isExpanded ? this.expandedIcon : this.collapsedIcon}
          outline={this.outline}
          disabled={this.disabled}
          onClick={this.handleToggle}
        >
        </spectrum-chip>
        {this.isExpanded && (
          <div class="spectrum-accordion__content">
            <slot></slot>
          </div>
        )}
      </div>
    );
  }
}
```

### Property Pass-Through Pattern
The accordion passes through relevant properties to the internal chip:

```typescript
// Property mapping for chip variant
<spectrum-chip
  variant={this.chipVariant}        // Maps to chip variant
  disabled={this.disabled}          // Direct pass-through
  outline={this.outline}            // Direct pass-through
  sound={this.sound}                // Pass-through for feedback
  haptic={this.haptic}              // Pass-through for feedback
>
```

### Event Delegation Pattern
The accordion handles chip events and emits its own standardized events:

```typescript
// Event handling and delegation
private handleChipClick = () => {
  this.isExpanded = !this.isExpanded;
  
  // Emit accordion-specific event with action context
  this.accordionToggle.emit({
    action: 'chip-toggle',
    expanded: this.isExpanded,
    accordionId: this.accordionId
  });
  
  // Handle feedback
  if (this.sound) this.soundTriggered.emit({ action: 'soundTriggered', accordionId: this.accordionId });
  if (this.haptic) this.hapticTriggered.emit({ action: 'hapticTriggered', accordionId: this.accordionId });
};
```

## 🔄 Event Flow

### Accordion Event System
1. User interaction (click, keyboard activation)
2. Internal chip handling (chip variant) or direct section handling (standard variant)
3. Accordion state update and animation
4. Accordion emits standardized events with action context
5. Parent component receives events for further processing

### Integration Event Examples

#### Conversation Panel Integration
```typescript
// Accordion usage in conversation panel
<spectrum-accordion
  variant="standard"
  expandMode="single"
  sections={this.contentSections}
  @accordionToggle=${this.handleContentToggle}
>
</spectrum-accordion>

// Event handling in conversation panel
handleContentToggle(event) {
  const { action, expanded, sectionId } = event.detail;
  
  // Update panel state
  this.updateContentVisibility(sectionId, expanded);
  
  // Emit panel-specific event
  this.panelAction.emit({
    action: 'content-section-toggle',
    source: 'accordion',
    sectionId,
    expanded
  });
}
```

#### FAQ System Integration
```typescript
// FAQ system with accordion
<spectrum-accordion
  variant="standard"
  expandMode="single"
  sections={this.faqSections}
  @accordionToggle=${this.handleFAQToggle}
>
</spectrum-accordion>

// FAQ-specific event handling
handleFAQToggle(event) {
  const { action, expanded, sectionId } = event.detail;
  
  // Track FAQ engagement
  this.analytics.track('faq_interaction', {
    question_id: sectionId,
    action: expanded ? 'expand' : 'collapse'
  });
}
```

## 🔧 Development Considerations

### When Modifying spectrum-accordion
1. **Chip Dependency Impact** - Changes to chip integration affect chip variant functionality
2. **Consumer Component Updates** - spectrum-conversation-panel depends on accordion behavior
3. **Event Contract Stability** - Ensure event payloads remain backward compatible
4. **Performance Testing** - Verify smooth operation with large section counts
5. **Accessibility Maintenance** - Test keyboard navigation and screen reader support

### Component Integration Checklist
When using spectrum-accordion in new components:

- [ ] **Variant Selection** - Choose appropriate variant for use case
- [ ] **Event Handling** - Define how accordion events integrate with component events
- [ ] **Content Strategy** - Plan for HTML content vs. slotted components
- [ ] **Performance Planning** - Consider section count and content complexity
- [ ] **Accessibility Integration** - Verify combined accessibility experience
- [ ] **Responsive Design** - Test accordion behavior across device sizes
- [ ] **Error Handling** - Handle invalid section data gracefully
