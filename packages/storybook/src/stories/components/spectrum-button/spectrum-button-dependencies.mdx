# 🔗 Spectrum Button Dependencies

This document shows the dependency relationships for the spectrum-button component and how it integrates with other components in the Spectrum system.

---

## 📋 Component Usage Overview

**spectrum-button** is a Level 1 atomic component with no internal dependencies. It provides core interactive button functionality and is the most widely used component in the Spectrum system, serving as a foundational element for 8 other components.

### Dependencies
- **None** (pure atomic component)

### Components Using spectrum-button

- **spectrum-conversation-panel** (chat interface actions)
- **spectrum-image-gallery** (upload and navigation controls)
- **spectrum-rail** (navigation triggers)
- **spectrum-rail-item** (individual navigation items)
- **spectrum-search-input** (voice search activation)
- **spectrum-select** (dropdown trigger)
- **spectrum-hero** (call-to-action buttons)
- **spectrum-accordion** (expandable content triggers via internal usage patterns)

## 🏗️ Architecture Integration

### Button Integration Pattern
The button component follows a consistent integration pattern across all dependent components:

```typescript
// Common integration pattern in dependent components
import { Component, h, Prop } from '@stencil/core';

@Component({
  tag: 'spectrum-example-component'
})
export class ExampleComponent {
  @Prop() buttonVariant?: 'primary' | 'secondary' | 'tertiary' = 'primary';
  @Prop() buttonSize?: 'small' | 'medium' | 'large' = 'medium';
  @Prop() disabled?: boolean = false;

  render() {
    return (
      <div class="example-component">
        <spectrum-button
          variant={this.buttonVariant}
          size={this.buttonSize}
          disabled={this.disabled}
          onClick={this.handleButtonClick}
        >
          Button Content
        </spectrum-button>
      </div>
    );
  }

  private handleButtonClick = () => {
    // Component-specific logic
  };
}
```

### Property Pass-Through Pattern
Dependent components typically pass through button properties:

```typescript
// spectrum-rail-item example
<spectrum-button
  variant={this.variant}
  size={this.size}
  disabled={this.disabled}
  class="rail-item__button"
>
  <slot></slot>
</spectrum-button>
```

### Event Delegation Pattern
```typescript
// spectrum-search-input example
<spectrum-button
  variant="tertiary"
  size="small"
  onClick={this.handleVoiceSearch}
  aria-label="Start voice search"
>
  <spectrum-icon name="mic"></spectrum-icon>
</spectrum-button>
```

## 🔄 Event Flow

### Standard Button Events
1. User interaction (click, keyboard activation)
2. Button emits standardized events
3. Parent component receives and processes events
4. Parent may emit its own events with context

### Integration Event Examples

#### Conversation Panel Integration
```typescript
// Button click in conversation panel
onButtonClick() {
  this.buttonAction.emit({
    action: 'send-message',
    source: 'conversation-panel',
    context: { messageId: this.messageId }
  });
}
```

#### Image Gallery Integration
```typescript
// Upload button in image gallery
onUploadClick() {
  this.galleryAction.emit({
    action: 'upload',
    source: 'image-gallery',
    context: { allowedTypes: ['image/*'] }
  });
}
```

## 🛠️ Implementation Notes

### Required Setup
```typescript
// No additional imports required - button is self-contained
import 'spectrum-button';
```

### Common Integration Patterns

#### 1. Wrapper Pattern (spectrum-rail-item)
```typescript
// Component wraps button and adds context
<spectrum-button class="rail-item__trigger">
  <slot></slot>
</spectrum-button>
```

#### 2. Trigger Pattern (spectrum-search-input)
```typescript
// Button triggers component-specific functionality
<spectrum-button onClick={this.activateVoiceSearch}>
  <spectrum-icon name="mic"></spectrum-icon>
</spectrum-button>
```

#### 3. Action Pattern (spectrum-conversation-panel)
```typescript
// Button performs component actions
<spectrum-button onClick={this.sendMessage}>
  Send
</spectrum-button>
```

### Performance Considerations
- Button component is optimized for frequent re-rendering
- Event listeners are efficiently managed
- CSS classes are cached for performance
- Accessibility attributes are computed once per render
